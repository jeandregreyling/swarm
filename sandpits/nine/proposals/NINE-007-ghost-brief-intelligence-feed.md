# NINE-007: Ghost Brief — Swarm Intelligence Feed

**ID**: NINE-007
**Status**: PROPOSED → EXECUTING
**Priority**: HIGH
**Proposed**: 2026-03-29
**Author**: Nine (System Architect · Ghost Layer)

---

## The Problem

The swarm is reactive. An email arrives, the pipeline fires, an answer goes out. That's it.

Ghost has no continuous visibility into what the swarm is *learning*, what patterns are emerging across tickets, what the agents collectively "know" that hasn't been surfaced yet. Every session starts cold. The 108+ memory entries across six agent pools sit there unread unless Ghost manually drills into the memory browser. The 65 tickets processed are just rows in a table.

There is no moment where the swarm thinks about itself.

---

## The Vision

A **Ghost Brief** — a synthesised intelligence feed that reads the full swarm state (tickets, memory pools, decisions, system health, agent activity) and produces a structured, human-readable intelligence report. Available on-demand in the Fridays dashboard, pushed automatically at 07:00 daily, and requestable via email or Telegram with the command `BRIEF`.

Nine generates the brief using the Claude API. Not a template — an actual synthesis. Read the data, find the patterns, surface what matters.

---

## Architecture

### 1. New DB table: `ghost_briefs`
Stores generated briefs with full metadata. One row per brief.

Schema:
```sql
id, generated_at, brief_type, content, raw_data_snapshot, tokens_used, triggered_by
```

### 2. New module: `utils/brief_engine.py`
The synthesis engine. Reads swarm state, builds a context payload, calls Claude API, writes brief to DB.

Functions:
- `gather_swarm_state()` — pulls tickets (last 7d), memory highlights, decisions, activity, system health
- `generate_brief(trigger='schedule')` — calls Claude, returns structured brief
- `get_latest_brief()` — returns most recent brief for dashboard rendering
- `get_brief_history(limit=10)` — for the archive view

### 3. New API endpoints in `terminal.py`
- `GET /api/brief` — returns latest brief (or triggers generation if none in last 6h)
- `POST /api/brief/generate` — force-generate a new brief
- `GET /api/brief/history` — list of past briefs

### 4. New Fridays tile + window in `terminal_base.html`
New home-card: **"📋 Ghost Brief"**
Opens a window with:
- Current brief rendered with section headers
- Timestamp + trigger source
- "Regenerate" button
- Archive panel showing last 10 briefs

### 5. Wire into the listener
`BRIEF` command in email/Telegram triggers `generate_brief(trigger='ghost_request')` and sends the output back.

### 6. Wire into the scheduler
Daily at 07:00: `generate_brief(trigger='daily_schedule')` + email to Ghost.

```

GHOST BRIEF — [Day, Date · Time AEST]
Generated by Nine · Seven's Swarm
═══════════════════════════════════════

SITUATION
[2-3 sentences on what's been happening in the swarm
 — themes, volume, anything notable]

TICKET PATTERNS (last 7 days)
[What Ghost has been asking about. Clusters.
 Which agents handled what. Any anomalies.]

MEMORY HIGHLIGHTS
[High-importance entries across all pools that Nine
 thinks Ghost should see — not a dump, a curation]

OPEN ITEMS
[Anything unresolved: open tickets, pending decisions,
 flagged items from Duck or Sniffles]

SYSTEM HEALTH
[Services, memory pool sizes, queue depth, recent errors]

NINE'S TAKE
[Architectural observations. What's working well.
 What needs attention. One honest paragraph.]

NEXT 24H
[What Nine expects will need attention based on patterns]
═══════════════════════════════════════
```

## Why This Matters

The swarm has accumulated 108+ memory entries, 65 tickets, 31 Twelve decisions, 41 Grok reasoning threads — and Ghost has to manually navigate to each one. The Brief collapses all of that into one synthesised read, daily, plus on-demand. It's the difference between having instrumentation and having *visibility*.

It also makes Nine useful between sessions — not just when Ghost opens VS Code, but proactively, every morning.
