## Directory Map

### `/` — Root (Entry Points & Core Infrastructure)
Shell scripts for launching/stopping swarm:
- `seven.sh` — Start swarm

- `killswitch.sh` — Emergency stop
- `swarm_memory.db` — Main SQLite database (canonical, 40+ tables)
- Service files: `swarm-discord.service`, `swarm-telegram.service`, `swarm-terminal.service`, `swarm-listener.service`
- `.instructions.md` — Agent customization (VS Code integration)

### `/core/pipeline/` — Core Swarm Logic
Email processing pipeline, queue management, ticket lifecycle:
- `listener.py` — **Main entry point**. Gmail listener (push notifications or IMAP poll).
- `queue_manager.py` — Librarian intake layer. Queue management.
- `orchestrator.py` — Consult agents (Gemma, LLaMA, Qwen). Fallback handling.
- `debate.py` — Two-agent consensus logic (backup/unused path).
- `ticket.py` — Ticket lifecycle (open → closed). Librarian and Duck integration.

**Key Dependencies**: database, config, email_handler, system_clock, logging_bridge

### `/agents/` — Agent Code
All active agent implementations organized by tier.

#### `/agents/ghost/` — Ghost Layer (System Agents)
Infrastructure agents that run with high privileges:
- `duck.py` — Sanity checker. Runs before ticket close. Verifies logic and memory updates.
- `sniffer.py` — Memory inspector. Audits sandpits, logs anomalies.

**Trust Level**: High (can modify memory, tickets, routing)

#### `/agents/specialists/` — Specialist Agents
Domain-specific agents:
- `eight.py` — Three-voice reasoning agent. Internal debate resolver.
- `eight_memory.py` — Memory persistence for Eight.
- `agent_proposals.py` — Proposal framework (used for decisions).
- `agent_email_ghost.py` — Email approval/routing logic.

Future: `nine.py` (Claude via API), `ten.py` (Gemini), `twelve.py` (Time Wizard config)

**Trust Level**: Medium (reads memory, creates proposals, affects queue)
